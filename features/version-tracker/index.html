ID: FEAT-046 Feature
TRACKER VERSIUNI

Prezentare generală

Tracker-ul de versiuni este mecanismul prin care peviitor.ro ține evidența tuturor versiunilor de frontend lansate vreodată. Fiecare versiune este înregistrată cu metadata completă, starea curentă și rezultatele verificărilor de compatibilitate.

Acest feature implementează cerințele definite în EPIC-016, oferind un registru public și un pipeline automat de verificare.

Structura datelor

Fiecare versiune este descrisă de următoarele câmpuri în fișierul versions.json:

Câmp Tip Obligatoriu Descriere
version string Da Numărul versiunii în format semver (ex: 1.0.0)
released date Da Data lansării, format ISO8601
status enum Da active / deprecated / archived
api_version string Da VERSiunea API consumată (ex: v1)
commit string Da Hash-ul commit-ului Git (7 caractere)
url string Da URL-ul public al versiunii
verified boolean Da Dacă a trecut testele de compatibilitate
last_verified date Nu Data ultimei verificări reușite
notes string Nu Notă opțională despre versiune (ex: "Fix autocomplete bug")

Exemplu de versiune

version: 2.1.0
released: 2026-06-15T10:00:00Z
status: active
api_version: v1
commit: a1b2c3d
url: https://peviitor.ro
verified: true
last_verified: 2026-06-26T02:00:00Z
notes: Versiunea curentă recomandată

Reguli de tranziție

Schimbarea stării unei versiuni respectă următoarele reguli:

De la Către Condiție
— active La lansare, automat
active deprecated Când o versiune nouă devine active
deprecated archived După 90 de zile de la deprecere
archived — Nu poate reveni (stare finală)

Pipeline de verificare

Un workflow GitHub Actions rulează automat pentru a verifica compatibilitatea fiecărei versiuni cu API-ul curent:

  1. Trigger — la fiecare deploy pe branch-ul main sau manual prin workflow_dispatch
  2. Încărcare versiuni — se citesc toate intrările din versions.json
  3. Test per versiune — pentru fiecare versiune se execută:
    • Build-ul frontend-ului din commit-ul specificat
    • 3 request-uri API simulate (search, filter, paginate)
    • Validarea structurii răspunsului (câmpuri, tipuri)
    • Verificarea încărcării fără erori JS
  4. Actualizare status — câmpul verified și last_verified sunt actualizați în versions.json
  5. Notificare — la eșec, se trimite un mesaj pe canalul Discord dedicat

Public endpoint

Datele sunt accesibile public la:

Endpoint Descriere
GET /versions.json Lista completă a versiunilor cu metadata
GET /versions/{version} Detalii despre o versiune specifică
